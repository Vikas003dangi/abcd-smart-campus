2. TWA Fundamentals

Q: “If I change or fix anything on the site, do I need to update the APK/AAB on Google Play Store?”

[!IMPORTANT] NO! You DO NOT need to build a new APK/AAB or republish to Google Play Store.

Why does this happen? (How TWA Works)

  • A traditional native app (built in Java, Kotlin, Flutter, or React Native) compiles code into a bundle. Every HTML/CSS/JS or logic change requires a new build and 2–3 days for Google review.
  • A Trusted Web Activity (TWA) is Google Chrome’s official technology that wraps your live website in a borderless, full-screen Android app shell.
  • When a student opens the ABCD app on Android, the shell instantly loads https://abcdcampus.in live from your Render server.
  • Result:
    • Whenever you push code to GitHub and Render redeploys, every single user’s app updates instantly in real time.
    • Bug fixes, new features in Guidy, library seat updates, audio changes, and design adjustments are reflected immediately with zero download or update required from Play Store!

When WOULD you ever need to republish a new AAB to Play Store?

Only in these 3 rare cases:

  1. You change the Android app icon that appears on the phone’s home screen.
  2. You change the splash screen background color or app name in Android OS settings.
  3. Once a year, Google Play requires bumping the target Android SDK version (e.g. from Android 14 to Android 15).

3. Background Notifications When Closed

Q: “How to ensure that even when tabs/browser are completely closed, Guidy messages, reminders, and alarms still ring on the device?”

The Delivery Flow:

flowchart TD A[Event Occurs: Guidy Message / To-Do Reminder / Seat Update] --> B[Django Backend users/notifications.py] B -->|VAPID Web Push Payload| C[Google FCM Push Server] C -->|Persistent OS Socket| D[Android Google Play Services on Phone] D -->|Wakes up in background| E[Service Worker static/sw.js] E -->|Reads sound, title, is_alarm| F[Plays Custom Audio & Displays Notification] F -->|If Alarm is ON| G[Rings alarm.mp3 continuously + Full Screen Modal] F -->|If Reminder| H[Plays alarms and reminders.mp3] F -->|If Guidy Message| I[Plays receive.mp3]

Why It Works Even With Browser Closed:

  1. The phone’s operating system maintains a permanent, ultra-low-power network connection to Google’s push servers via Google Play Services.
  2. When your server sends a push notification, Google’s servers wake up your Service Worker on the user’s phone, even if Chrome, the browser, and the ABCD app are closed or killed from recent tasks.
  3. The Service Worker receives the push event, reads the payload (sound, is_alarm, category), and calls self.registration.showNotification().

Crucial Steps on the User’s Phone:

Modern Android versions (Android 13+) and aggressive phone skins (MIUI/Xiaomi, Realme, Vivo, Oppo, Samsung) have aggressive battery optimizations. To ensure 100% instant ring:

  1. Notification Permission: Android 13+ asks: “Allow ABCD Campus to send notifications?” The user must tap Allow.
  2. Battery Optimization (For Alarms): In phone Settings → Apps → ABCD Campus → Battery, recommend setting to “Unrestricted”.
  3. Auto-Start (MIUI/Vivo/Oppo): Enable “Autostart” so background alarms fire on schedule even after device reboot.

4. Step-by-Step Generation

You need two files:

  • .apk: For installing directly on your Android phone to test immediately before publishing.
  • .aab (Android App Bundle): The exact format required by Google Play Console for store upload.

Method 1: PWABuilder (Recommended — Zero Java/SDK Setup)

PWABuilder is Microsoft’s official open-source tool that uses Google’s Bubblewrap on cloud build servers. You don’t need to install Java, Android Studio, or Android SDK on your computer.

  1. Open https://www.pwabuilder.com in your browser.
  2. Enter your live domain: https://abcdcampus.in and click Start.
  3. PWABuilder will audit your PWA (Manifest, Service Worker, Security) — you will get a high score because your manifest and service worker are already compliant.
  4. Click Package for Stores → Choose Android → Click Generate.
  5. In the Android Package Options dialog, fill in:
    • Package ID: in.abcdcampus.app
    • App Name: ABCD Coaching & Library
    • Short Name: ABCD Campus
    • Version Name: 1.0.0
    • Version Code: 1
    • Display Mode: Standalone
    • Status Bar Color: #e09fd5
    • Nav Bar Color: #854c7a
    • Splash Screen Color: #854c7a
    • Notifications: Check Enable Web Push Notifications and Notification Delegation.
  6. Signing Key:
    • Choose Create New Keystore.
    • Fill in your details (Alias: abcd, Password: create a strong password).

    • [!CAUTION] Download and save this .keystore file and its password in Google Drive or a safe backup! You need this key whenever you want to update the app in the future.

  7. Click Generate Bundle.
  8. PWABuilder will compile and provide a .zip download containing:
    • app-release-bundle.aab (upload this to Play Store)
    • app-release.apk (install this on your phone to test)
    • assetlinks.json (contains your SHA-256 fingerprint!)

Method 2: Local Bubblewrap CLI

If you prefer running the build locally on your Windows command prompt:

  1. Install Java JDK 17:
    • Download from Adoptium Temurin 17 or install via PowerShell:
      winget install EclipseAdoptium.Temurin.17.JDK
  2. Install Bubblewrap globally:
    npm install -g @bubblewrap/cli
  3. Initialize the TWA:
    mkdir b:\ABCD\abcd-twa
cd b:\ABCD\abcd-twa
bubblewrap init --manifest=https://abcdcampus.in/static/data/favicon/site.webmanifest
    (Bubblewrap will auto-download the Android command-line SDK tools and prompt you to create a keystore).
  4. Build APK and AAB:
    bubblewrap build

6. Digital Asset Links & App Signing

[!WARNING] The Most Common Mistake: When you upload your .aab to Google Play, Google uses Google Play App Signing. Google re-signs your app with their private key. If Google’s SHA-256 fingerprint is not in assetlinks.json, the browser URL bar will show up at the top of your app!

How to Fix This in 2 Minutes:

  1. In Google Play Console, navigate to Setup → App Integrity.
  2. Under App Signing, find the section “App signing key certificate”.
  3. Copy the SHA-256 certificate fingerprint (it looks like 12:34:56:78:AB:CD:...).
  4. In your Render Dashboard:
    • Go to Environment Variables.
    • Add/Update:
      TWA_SHA256_FINGERPRINT=YOUR_COPIED_SHA256_HERE
    • If you want both local test APKs and Play Store to work simultaneously, you can pass comma-separated fingerprints or update users/views.py to support multiple fingerprints.
  5. Verify your endpoint in your browser:
    https://abcdcampus.in/.well-known/assetlinks.json
  6. Google will automatically verify the domain ownership within a few hours. Once verified, the URL bar disappears completely, giving users a 100% native full-screen experience.

7. Smart Banner & Install Strategy

Q: “What should happen when the user visits from a mobile browser? Should we prompt browser install or redirect to Play Store?”

What Big Tech Does (Twitter, LinkedIn, Flipkart, Reddit):

On Android mobile browsers:

  1. Redirect to Google Play Store is the Golden Standard:
    • In India, 95%+ of students prefer installing from the Google Play Store rather than a browser popup.
    • Play Store provides the recognizable “Verified by Play Protect” seal, auto-updates, and instant credibility.
  2. Behavior Matrix:
    • On Android Mobile: When user taps INSTALL in your top smart banner or modal, redirect them directly to:
      market://details?id=in.abcdcampus.app
      (Fallback: https://play.google.com/store/apps/details?id=in.abcdcampus.app). This opens the Google Play Store app directly on their phone with a big green Install button!
    • If App is Already Installed on Phone: Your code in [app-install-prompt.js](file:///b:/ABCD/abcd_web/static/js/app-install-prompt.js) automatically detects it via getInstalledRelatedApps() and changes the banner button to OPEN. Tapping it launches the app immediately via the native Android Intent!
    • On iOS / iPhone: Google Play Store doesn’t exist on iOS. The modal automatically displays the iOS Safari instructions: “Tap Share → Add to Home Screen”.

8. Installing on Desktops & Laptops

Q: “Can our app be installed on laptops and desktops too?”

[!NOTE] YES! On Windows, Mac, and Linux, your app installs as a Desktop PWA.

How Desktop Users Install ABCD:

  1. When visiting https://abcdcampus.in on Google Chrome or Microsoft Edge on a laptop:
    • A small “Install ABCD Campus” icon (an icon with a computer and down arrow) appears in the browser’s URL address bar on the right.
    • Or, clicking Install App in the navigation menu triggers the native desktop install prompt.
  2. Once installed:
    • An ABCD Coaching & Library shortcut is added to the Windows Desktop and Start Menu.
    • The app opens in its own dedicated, clean window without browser tabs or address bars.
    • Supports native Windows notifications!
  3. Chromebooks (ChromeOS):
    • Chromebooks natively support the Google Play Store! Students on Chromebooks can download the exact same Play Store app.
